# 面对面翻译（中文 ↔ 韩语）设计

状态：待用户批准。标注 **【已定】** 是用户决定的，**【我定的】** 是执行者的判断，可以推翻。

## 目的

两个人面对面共用一台 iPhone 交谈：一方说中文，另一方看到韩语；对方说韩语，机主看到中文。全程端上完成。

## 目标与不做的事

- **【已定】** 第一版只显示中文和韩语的文字，不朗读。
- **【已定】** 用两个按钮表明谁在说话。
- **【我定的】** 只做中文 ↔ 韩语；不做其他语言对，不做自动语言识别，不做同时说话。
- ~~**【我定的】** 对话不保存到手机，离开页面或杀掉 App 就清空；不进会议记录库。~~ **已被用户 2026-11-28 的决定替代：** 对话的文字（不含录音）保存到手机，可在"历史记录"里查看、复制、导出、分享和删除（见 `docs/superpowers/plans/2026-11-28-history-export.md`）。离开页面仍清空屏幕上的对话，但已保存的记录保留。对话存在单独的实体里，不混进会议的 `Meeting` / `Segment`。每次进入本页最多一条记录，第一句完成时才创建；说完并显示出来的句子都保存（翻译失败的存原文）。被丢弃的一次（第 8 步，或关闭本页时还在收尾、翻译中或等回到前台的那一句）只要已经识别出文字，也保存原话，译文记为空，历史记录和导出里显示"（未翻译）"；它不会出现在对话屏幕上。没有识别出文字的不保存。这一次还没结束时 App 被系统杀掉，仍会丢失。保存失败不影响对话，中文一半提示"这条对话没有保存"。
- 反目标：为了这个功能让现有的会议字幕变差或变复杂；出现任何联网代码；识别错了说话人却看不出来。

## 现状（代码里的事实）

- `ASREngine.transcribe(_:locale:)` 已按传入语言工作；`AudioSource`/`AudioCapture` 可复用（录音类别为 `.record`，系统中断时流会结束）。
- `Translator` 协议只有源语言参数，目标语言是写死的 `TranslationTarget.language`（简体中文）；`AppleTranslator` 按源语言缓存会话。中文 → 韩语现在做不了。
- 引导页的 `OnboardingModel`、自检样本和 `ModelReadiness` 都围绕"某源语言 → 中文"。
- MacBook Air（不是 iPhone）上查到：中文、韩语语音识别受支持；`zh-Hans → ko`、`ko → zh-Hans` 翻译可用。
- App 已在 iPhone 18 Pro Max 上跑通过英语识别翻译；韩语自检在手机上通过过。

## 做法的选择（用户已选）

1. **两个按钮（选中）：** 各按各的，识别语言确定，最可靠；每句要点一下。
2. 一个切换键轮流：点得少，一方连说两句就认错语言。
3. 自动判断语言：要两个识别器同时听再挑结果，效果无把握。

## 界面

```
┌──────────────────┐
│  整块倒置，朝向对方 │
│  韩语对话记录      │
│  [ 말하기 ]       │
├──────────────────┤
│  中文对话记录      │
│  [ 我说中文 ]  ✕  │
└──────────────────┘
```

- **【我定的】** 上下两半显示**同一段对话**，每半只用自己的语言：下半全部中文，上半全部韩语。每一条里，说话人那一半显示的是识别出的原话（他能当场看出认错没有），另一半显示译文。两种来源用样式区分（原话次要色，译文主色大字）。
- 最新一条在各半的底部（以各自朝向为准），自动滚到最新。
- 上半区的按钮和提示文字用韩语。
- **【我定的】** 进入方式：字幕页顶部和引导页各有一个"面对面"按钮（会议语言包没装好的人也能进，本功能自己检查四样语言包）；字幕页上的按钮只在会议未进行时可用；页面上有关闭按钮回到来处。
- 屏幕在本页保持常亮；离开时恢复。

## 一次说话的流程

1. **【我定的】** 点自己的按钮开始听（点一下，不用按住）。另一方的按钮此时禁用。**【我定的】** 录音真正开始后才显示"在听"的状态，8 秒和 60 秒从这时起算。先按每次说话单独启停录音和识别做；只有真机上发现开头几个字丢失，才改成进页面时保持开启。
2. 听的过程中，说话人那一半实时显示临时识别文字。
3. 结束条件：再点一次按钮，或识别结果约 2 秒没有变化（停顿时限沿用现有配置的值），或到达 60 秒上限（**【我定的】**）。还没出现任何识别文字时，停顿不结束，**【我定的】** 8 秒仍无文字则结束并提示"没听清"。
4. 结束后等识别收尾，把整段话作为一条翻译，成功后两半同时出现这一条。
5. 翻译失败：说话人那半保留原话，另一半显示"翻译失败"；不重试队列，再说一遍即可。
6. 没有识别到任何文字：不新增条目。
7. 识别或录音出错、来电打断：结束本次，保留已识别的部分按第 4 步处理，没有则提示出错原因。
8. 离开页面或进入后台：停止听，丢弃未完成的这一次（屏幕上不出现；已识别出的文字仍按上面的规则存入历史记录）。只有真正进入后台才算，下拉控制中心或通知横幅不打断。
9. **【我定的】** 来电时中断先到：本次立即结束，已听到的部分保留；翻译等回到前台再做（此时第 8 步不丢弃它）。

## 语言包

本功能需要四样：中文识别包、韩语识别包、中→韩翻译、韩→中翻译。

- **【我定的】** 进入页面时检查四样；缺哪样列哪样，给一个"下载"按钮按现有方式处理（识别包由 App 安装；翻译包经系统的下载界面）。全部齐了才出现对话界面。
- **【我定的】** 不做合成语音自检；直接使用，出错时按上面的流程提示。
- **【我定的】** 中文识别固定用 `zh-CN`（只写 `zh` 可能匹配到 zh-TW 或 zh-HK）；翻译语言对固定为 `zh-Hans` ↔ `ko`，检查与下载用的必须完全是这一对，定义只写一处。
- 识别语言的"保留"名额：MacBook Air 上 `AssetInventory.maximumReservedLocales` 是 5，英、韩、中三种放得下（iPhone 上未确认）。如果仍然超限，显示原因，**绝不悄悄释放**其他语言。
- 现有会议功能的引导和自检保持原样。

## 核心包的改动

- 翻译需要能指定目标语言；会议功能仍固定为简体中文，行为不变。缓存的翻译会话按语言对区分。
- 一次说话的状态机（空闲、在听、收尾、翻译中）放在核心包，不依赖 SwiftUI，用假引擎、假音频、假翻译做测试；视图只做显示和转发点击。
- 面对面功能与会议协调器不能同时占用麦克风。
- 不改会议记录的存储结构。

## 约束

沿用项目现有约束：Swift 6、警告当错误、单个源文件不超过 200 行、无第三方依赖、无网络代码、CI 编译 iOS 26/27 部分。iPhone 竖屏优先。

## 验收（真机，结果由用户填写）

联网下载四样语言包 → 开飞行模式（来电一项除外，需关飞行模式测） → 两人各说三句短话，每句两半都正确出现；停顿自动结束；一方在听时另一方按钮不可用；来电或切后台后回来能继续用；回到字幕页后会议字幕功能照常。
