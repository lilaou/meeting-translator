# 韩语 → 中文（开会前选语言）

分支 `feature/korean-source`，从 `main`（37ca9e9）切出。用户决定：一场会议只用一种语言，开会前选定；不做自动识别，不做同一场内切换；做完后与英语一起验收。

## 现状

- 核心包的识别、翻译、引导、存储本来就按传入的 `Locale` 工作。
- 写死英语的地方：App 的 `AppAssembly.sourceLocale`；自检的朗读句子、关键词 `meeting`、试翻译句子（`ReadinessLogic`）和合成语音 `en-US`（`SynthesizedSpeech`）。不改的话韩语自检必然失败。
- MacBook Air（macOS，不是 iPhone）上查到：`SpeechTranscriber.supportedLocales` 含 `ko-KR`，韩语到 `zh-Hans` 翻译为 `supported`。iPhone 上未确认。

## 做什么

### 核心包
- 一个公开的受支持源语言清单（单一来源）：`en-US`、`ko-KR`。每种语言带自检样本：朗读句子、识别应命中的关键词、试翻译句子、合成语音语言。
  - 英语沿用现有内容。
  - 韩语：朗读 `회의는 내일 아침 아홉 시에 시작합니다.`，关键词 `회의`，试翻译 `회의는 아홉 시에 시작합니다.`，语音 `ko-KR`。
- 自检按传入的 `locale` 选样本和语音；清单之外的语言给出可读的失败原因（中文），不崩溃。匹配按语言代码（`en-GB` 用英语样本），语音语言跟样本走。
- 先写测试：两种语言各自的通过与失败（关键词缺失、译文无汉字）、合成语音拿到的语言、清单外语言；现有测试的意图不削弱。
- 韩语切句的测试：用 `.`、`?` 结尾的韩语句子能切开，词间空格保留；超长时在空格处切。若现有 `SentenceAssembler` 已满足就只加测试。

### App
- 引导页顶部加语言选择（分段控件：英语 / 韩语），名称用 `CaptionStrings` 的中文语言名。只在没有任务进行时可改（`isBusy` 为假且步骤不是安装、下载、自检中）。
- 选择记在 `UserDefaults`（只存语言标识），默认 `en-US`；存了清单外的值时回退到默认。
- 换语言时丢弃旧的 `OnboardingModel`（先 `cancel()`），为新语言建一个并 `refresh()`；`ModelReadiness`、协调器仍然只有一份。
- `coordinator.start(locale:)`、顶栏方向、翻译下载语言对全部取当前选择，不再有写死的 `en-US`（预览除外）。会议进行中不能改语言。
- 字幕页在 `idle` 和 `failed` 时提供"更换语言"，回到引导页；`preparing`、`listening`、`finishing` 时不提供。已有的"检查语言包"保留。
- 视图仍然不写 SwiftData；不加网络代码；文件不超过 200 行；Swift 6、警告当错误。

### 文档
- `README.md`、`docs/phase1-acceptance.md`：写明支持英语和韩语；验收表在韩语下需要再走第 3、6、7 项，作为附加行列出，结果留空。不写任何未验证的结论。
- 设计文档第 22 行"其他语言不需要改代码"不准确：加一句更正说明（自检样本需要按语言提供），不改其余内容。
- 契约文档真机清单加韩语项：语音包与翻译包能否下载、设备是否有韩语合成语音、自检能否通过、识别质量、200 字符上限和 2 秒停顿对韩语是否合适。

## 验收标准

1. CI 全绿，编译器 0 警告（Xcode AppIntents 提示除外）；本地 `swift test` 全过。
2. 英语行为不变（同样的自检样本、同样的流程）。
3. 无法本机运行的部分（韩语语言包、语音、识别效果）全部记为未验证。

## 不做

自动语言识别、会议中切换、日语等其他语言、历史页、按语言调参。
