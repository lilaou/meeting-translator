## 1. 执行前提

- **Apple 芯片的 Mac**，macOS 26.6 或更高，装有 Xcode 27.x。据 Apple 开发者论坛的帖子（<https://developer.apple.com/forums/thread/829619>）报道，Xcode 27 不能在 Intel Mac 上运行，且运行 iOS 27 的 iPhone 需要 Xcode 27 才能部署；这是帖子里的说法，未对照 Apple 官方页面核实（审阅时未能打开该帖子）。另据 Homebrew 支持层级页面（<https://docs.brew.sh/Support-Tiers>），macOS Tahoe 26 是最后一个能在 Intel 硬件上运行的 macOS。项目现在有一台满足条件的 Apple 芯片 Mac（Xcode 27.2）；Intel 那台（macOS 15，Xcode 16.4）只能跑核心包的测试。
- **Phase 0 和 Task 5 尚未做**：Task 1（Probe 与 `docs/phase0-results.md`）和依赖它的 Task 5（真实片段回放校验，同时校准 `PipelineConfig`）都没有运行，仓库里没有 Probe 工程、Phase 0 结果或回放数据。第 4 项需要 Probe 日志，所以必须先完成 Task 1。
- iPhone 运行 iOS 27.x，已开启开发者模式（设置 → 隐私与安全性 → 开发者模式），用数据线连到 Mac 并信任。
- 复制 `Local.xcconfig.example` 为 `Local.xcconfig`（已被 git 忽略），填入自己的团队 ID。不要提交这个文件。
- 在项目根目录运行 `xcodegen generate` 生成工程（`.xcodeproj` 不进仓库），用 Xcode 选择真机运行 `MeetingTranslator`。
- 手机首次需要联网下载英语识别和翻译语言包，之后才能进入飞行模式。验收韩语时，还要在引导页选"韩语"（启动时若直接进了字幕页，先点"更换语言"），联网下载韩语的识别和翻译语言包并通过自检。
- 第 3、4 项需要一段**至少 10 分钟**、许可清晰的英语录音。它可以是 Phase 0 Task 1 的公开基准录音，可以比包里真机测试用的 `benchmark-en.wav`（约 1–3 分钟，见 [Fixtures/README.md](../Packages/MeetingCore/Tests/MeetingCoreTests/Fixtures/README.md)）更长。**录音不在仓库里**，需要你自行提供，许可必须允许再分发（仓库是公开的）；私人会议录音放在被忽略的 `recordings/` 目录，不要放进 Fixtures。第 4 项对照的是 Probe 对**同一段**录音的 final 文本。

## 3. 顺手核对的清单与待定决定

契约文档 [`docs/superpowers/notes/2026-11-21-engine-contracts.md`](superpowers/notes/2026-11-21-engine-contracts.md) 维护两份清单，验收时一并处理。这里只引用，不复制条目，以免两份清单不一致：

- 「真机验证清单（需要真机）」：该节的每一条都要在真机上确认，包括 11d 字幕页的各子项和标注"有条件"的那一条。
- 「待定的设计决定」：该节目前列出翻译收尾的超时策略。

验收时要顺手回答三个尚未决定的问题，答案写进"备注"或另开记录：

1. **翻译收尾的超时**：`translationDrainTimeout` 是否应改成"没有进展才超时"，并让界面显示"正在完成翻译…"（契约文档「待定的设计决定」）。
2. **会后可重试**：设计规格（`docs/superpowers/specs/2026-11-20-meeting-translator-design.md`）第 160 行写"翻译失败的句子保留原文，会后可重试"，但 Phase 1 没有重试，被放弃的句子的译文不会再补上。要么实现重试，要么改规格。
3. **语言区域的预留（reserve）**：当系统早已装有识别模型、引导流程从不调用 `installSpeechPack` 时，语言区域从未被预留，自检可能一直失败（契约文档「真机验证清单」中标注"有条件"的那一条）。需要真机上确认并决定补救方式。

## 4. 运行包里的真机测试

未验证。包里的真机测试默认跳过，环境变量 `RUN_DEVICE_TESTS=1` 才会运行：

先试（xcodebuild 会把带 `TEST_RUNNER_` 前缀的环境变量转给测试进程）：

```bash
cd Packages/MeetingCore
TEST_RUNNER_RUN_DEVICE_TESTS=1 xcodebuild test -scheme MeetingCore \
  -destination 'platform=iOS,name=<设备名>'
```

不行的话，在该 scheme 的 Test 环境变量里设置 `RUN_DEVICE_TESTS=1`。

注意：

- 这条命令本身没有在真机上试过，环境变量能否传到设备上的测试进程要实际确认。仓库里没有应用承载的测试目标；如果测试需要宿主应用，再加测试目标。
- CI 只做 `build-for-testing`（编译包的测试代码给 iOS 模拟器），不运行它们。
- `AppleSpeechEngineDeviceTests` 需要基准录音 `benchmark-en.wav` 和 `benchmark-en.txt`。它们**不在仓库里**，需要用户自行提供，且许可必须清楚地允许再分发；缺失时测试会跳过并说明缺哪个文件。详见 `Packages/MeetingCore/Tests/MeetingCoreTests/Fixtures/README.md`。
- 设备上还需要已安装英语语音资源（iOS 26 或更高）。

## 5. 失败时怎么办

任何一项不符合预期：

1. 用 `superpowers:systematic-debugging` 先找到根本原因，不要凭猜测改代码。
2. 在对应任务的测试里补一条能复现它的用例（先看到它失败），再修复。
3. 修复后**重跑整张表**，不只重跑失败的那一项。
